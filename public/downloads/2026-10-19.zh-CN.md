## 升级

1. 同步已购买的 viewer 源码仓，将它们放在 `office-render-demo` 相邻目录。
2. 按各仓锁文件与 README 安装依赖，使用 Node.js 24 工具链构建。
3. 在综合 Demo 运行 `npm --userconfig=/dev/null run build:all`，完整重建组件及集成页面。
4. 仅发布同一次构建的完整 `dist/`，保留订单交付的许可证和项目字体配置。
5. 清理或刷新旧入口缓存，用实际业务文件检查首屏、最终字体、翻页、滚动、选区和文件切换。

不要混用不同构建的入口、分块、Worker、WASM 与样式，也不要直接替换某一个生成文件。

## 接入

- 综合网页：通过同源文件 URL 与 iframe 或独立页面接入。
- 已有 file-viewer：保留文件权限、登录、列表、下载及非 Office 预览，只分流 Office 文件。
- Windows 桌面：参照 `examples/wpf-webview2/README.md`，使用显式格式、无扩展名路径或只读文件流，并接收渲染状态。
- 说明与配置下载：[Office Preview 文档中心](https://officejs-doc.pages.dev/#file-viewer-migration)。

## 验收与边界

DOCX 四份公开样例的页数与生命周期检查为 17、4、3、75 页，包含远页激活、常驻页面预算和打印后恢复。页数通过不代表所有文件逐像素等同原生 Word。字体完成后的最终页面才用于版式评估；首屏先读与最终布局是不同阶段。

大工作表按视窗载入和渲染，选区不创建与选中范围同样规模的 DOM。实际文件能否顺畅运行还取决于结构、媒体、客户端内存和浏览器，请使用代表性大表验收，不能只按文件大小判断。

旧 XLS 图片本轮覆盖内嵌 PNG/JPEG；WMF/EMF/DIB、组合图形和外链图片不属于该新增路径的支持承诺。

默认字体服务需要网络。内网及离线项目应准备具有使用权的本地字体与静态资源，并确认 CSP、跨域和字体服务可达性。
