## Upgrade

1. Synchronize the licensed viewer repositories alongside `office-render-demo`.
2. Install according to each repository's lockfile and README, using Node.js 24.
3. Run `npm --userconfig=/dev/null run build:all` in the integrated demo to rebuild the components and application.
4. Publish only the complete `dist/` from that build, retaining the delivered license and project font configuration.
5. Refresh cached entry files and assess first display, final fonts, pagination, scrolling, selection and document switching with representative files.

Do not mix entry files, chunks, Workers, WASM or styles from different builds, or manually replace a generated module in isolation.

## Integration

- Web applications: embed the preview page or open it directly using a same-origin file URL.
- Existing file-viewer: retain authentication, file permissions, lists, downloads and non-Office preview; route only Office files to this renderer.
- Windows desktop: follow `examples/wpf-webview2/README.md` for explicit format selection, extensionless paths, read-only streams and status events.
- Guides and downloadable configuration: [Office Preview documentation](https://officejs-doc.pages.dev/#file-viewer-migration).

## Acceptance and Scope

The four public DOCX page-count and lifecycle checks retain 17, 4, 3 and 75 pages, including far-page activation, residency limits and restoration after printing. Matching page counts does not establish pixel equivalence with native Word. Assess final typography after font and layout calibration; first readable display and final layout are separate milestones.

Large worksheets load and render viewport windows. A selection does not create DOM proportional to the selected range. Actual performance depends on workbook structure, media, client memory and browser; assess representative large files rather than file size alone.

The new legacy XLS picture path covers embedded PNG/JPEG. It does not imply support for all WMF/EMF/DIB pictures, grouped drawings or external images.

The default font service requires a network connection. Intranet and offline projects need properly licensed local fonts and assets, with appropriate CSP, CORS and reachable font resources.
